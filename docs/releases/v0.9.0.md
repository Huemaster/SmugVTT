# SmugVTT v0.9.0 — first integrated public source release

**Three Pillars. One Tabletop.**

SmugVTT v0.9.0 is the first public source release that brings the fork's integrated Map, Chat, Canvas, Scene and optional tactical/unit-management work into one reviewable codebase. It builds on the substantial VTT foundation inherited from [CozyVTT](https://github.com/CheekyChinchilla/CozyVTT); this is **not** a claim that SmugVTT invented its map engine, accounts, sheets, chat, dice, or original hosting stack.

This is a **self-hosted source release**. It is **not** a hosted service, a ready-to-run Windows EXE, or a guest/demo website. GMs install the server; players join using their web browser.

## Release highlights

### 1. Map-first tactical workflow without losing the rest of the table

- More flexible map workspace and panel access, with Chat, Journal/handouts, Media and Dice available beside a large map.
- Consistent map token interaction: **click or tap to select; press, drag and release to move**. A click alone never starts a pick-up/drop cycle.
- Keyboard token movement for eligible selections; improved touch and desktop handling, including Escape cancellation and relevant tool interactions.
- More useful on-map token details, hover/status feedback, and room for system-specific quick actions.
- The underlying map, fog, walls, lighting, ruler, drawing and campaign features remain based largely on CozyVTT; SmugVTT's additions integrate with, rather than replace, them.

### 2. Chat as a main play surface

- Character-oriented speaker identity, in-character presentation, portrait-aware interaction and Scene dialogue integration.
- Improvements to recipient selection, responsive chat layout, compact panel access and persistent history behavior.
- Moderation endpoints for edits, revision history, soft deletion and restoration, with GM/non-GM permission tests and restricted whisper behavior.
- A saved chat mutation remains a successful REST operation even if Socket.IO is temporarily unavailable for the follow-up broadcast. Logs omit the private mutation payload.
- Existing whisper functionality is inherited from CozyVTT and is **not end-to-end encryption**. Server administrators can access stored messages and backups.

### 3. Scene and Canvas presentation

- Saved visual boards and staging integrated with campaign/scene state.
- A Stage view that presents **canonical in-character chat**, rather than creating a second chat history.
- Support for positioning participants, portraits and backgrounds and connecting live dialogue to visual staging.
- Scene endpoints for GM management and visibility-aware reads; extra rights remain subject to campaign permissions.
- This is an actively evolving interaction model. GMs should verify GM-only content and player visibility with a separate account before using sensitive campaign material.

### 4. Optional Squad Command and NPC tooling

- A selectable **Squad Command** integration in the public codebase; other game systems do not have to adopt it.
- Generic character sheet, unit-oriented controls and compact combat UI that can display relevant health/defense/shield/suppression-style information.
- GM-facing NPC and sheetless-unit concepts, reusable units, targeting feedback and action presentation hooks.
- Generic public examples are intentionally small. No private campaign roster, world bible or chat export is included as an example.
- Not every specialized rule, status interaction or cleanup flow is automatic or complete. Use it as an evolving optional layer and report edge cases.

### 5. Battlefield overlays and GM assistance

- Visual zones for cover, elevation, smoke, hazards and other context.
- Editable shapes, fill and texture treatments, visibility options and contextual token feedback.
- Position-aware assistance where supported, plus explicit GM-controlled healing/area actions.
- Tactical annotations are optional aids. They do not replace the rules or adjudication of each group's chosen system.

## Installation

Recommended: Docker Compose with unique secrets. The database and backend remain behind the bundled reverse proxy. Players access the app from their browser; they never need Docker.

~~~bash
git clone https://github.com/Huemaster/SmugVTT.git
cd SmugVTT
cp .env.example .env
# Edit .env and set unique DATABASE_PASSWORD and SESSION_SECRET
docker compose up -d --build
docker compose logs backend
~~~

Open **http://localhost** and complete the setup wizard using the startup token. For a public server, follow [Deployment](../../docs/DEPLOYMENT.md) for HTTPS, CORS, secure proxying, backups and registration controls.

The manual alternative is Node.js **26+**, PostgreSQL **15**, built frontend/backend and an HTTP reverse proxy. See [Manual Deployment](../DEPLOYMENT.md#manual-deployment). There is no one-click Docker-free download in v0.9.0.

## Upgrading from an older local or public build

**Back up before upgrading.**

1. Save a PostgreSQL database backup and a copy of **backend/uploads/**; keep both private.
2. Test a restore to a disposable instance if the database includes important player or campaign history.
3. Review any locally applied patch ZIPs or edits. The public repository may have integrated similar changes differently; do not blindly copy an old patch over v0.9.0.
4. Update the public source and rebuild the production stack.
5. Check migration logs, admin setup/login, campaign list, token movement, chat, Scene permissions, and optional rule-specific tools as both a GM and an ordinary player.

~~~bash
git pull origin main
docker compose up -d --build
docker compose logs backend
~~~

If a database downgrade is needed, use the backup taken before upgrading. An older code snapshot may not understand new stored records.

**Upstream compatibility:** SmugVTT does not automatically incorporate all later CozyVTT releases. In particular, CozyVTT 1.7.0 introduces game-system and role migrations that must **not** be applied wholesale to this fork without a compatibility review. This release keeps the fork's existing persisted identifiers where necessary.

## Limits and known follow-ups

- No hosted anonymous trial, disposable guest demo, or portable Windows installer yet.
- Scene staging, shared visibility, player permissions and persistence need continued real-table regression and usability testing.
- Optional Squad Command rule enforcement, specialized abilities, imported records and advanced status/overlay edge cases remain ongoing work.
- The repository includes an AGPL source distribution, not a hosted service or a promise of support for every deployment.
- GitHub release archives are source archives. The recommended runtime packaging still uses Docker Compose.
- A release does not grant permission to upload other users' campaign data or reuse private local sample material.

## Privacy, credits and license

Only generic, fictional examples belong in the public repository. The source release should contain no private campaign exports, player chat logs, personal file paths, uploaded asset libraries, credentials, database dumps, or private rulebook content.

SmugVTT remains an independently maintained fork of **CozyVTT**. The original authors and contributors retain credit for the inherited VTT and its design. SmugVTT is not endorsed by CozyVTT. The code remains **AGPL-3.0-only**, with original and third-party attribution preserved.
